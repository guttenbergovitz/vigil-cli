# ADR 010: Java Ecosystem Support (Maven & Gradle)

## Status

Accepted

## Context

Vigil CLI provides multi-ecosystem Software Composition Analysis (SCA) for JavaScript/TypeScript, Python, Rust, PHP, and Go.
Java is one of the most widely used enterprise languages, with Maven and Gradle as its dominant build systems and dependency managers.

To support Java projects in Vigil CLI, we need parsers for:
1. **Maven (`pom.xml`)**: Standard XML project object model containing dependencies defined via `<groupId>`, `<artifactId>`, and `<version>`.
2. **Gradle (`gradle.lockfile`)**: Dependency lockfile generated by Gradle's dependency locking feature containing exact resolution state (`group:artifact:version=classpath`).

## Decision

Extend Vigil CLI with Java ecosystem support under `EcosystemMaven`:

### 1. Ecosystem & Lockfile Types
- Add `EcosystemMaven` (`"Maven"`) in `internal/types/types.go`.
- Add `PomXml` (`"pom.xml"`) and `GradleLockfile` (`"gradle.lockfile"`) in `internal/lockfile/parse.go`.
- Map PURL generation in `internal/osv/client.go`: `pkg:maven/{groupId}/{artifactId}@{version}` (e.g. `pkg:maven/org.apache.logging.log4j/log4j-core@2.14.1`).

### 2. Maven XML Parser (`parsePomXml`)
- Use Go's standard `encoding/xml` parser to extract `<dependency>` items.
- Resolve XML properties (e.g. `<properties><log4j.version>2.14.1</log4j.version></properties>`) referenced via `${property.name}`.
- Skip dependencies missing concrete versions or marked with `<scope>test</scope>` when dev dependencies are skipped.

### 3. Gradle Lockfile Parser (`parseGradleLockfile`)
- Parse line-based `gradle.lockfile` entries matching `group:artifact:version=classpaths`.
- Ignore comment lines beginning with `#` or empty lines.

## Consequences

### Positive
- Enables enterprise Java/Kotlin application vulnerability scanning.
- Supports both Maven and Gradle build tools with 100% native Go XML and line parsing (zero external dependencies).
- Accurately queries OSV database using standard Maven PURL spec.

### Negative
- Maven POM inheritance (`<parent>`) across multi-module projects requires property resolution fallback when versions are managed at root.
